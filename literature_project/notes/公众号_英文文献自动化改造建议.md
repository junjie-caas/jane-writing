# 从“能跑”到“可规模化”：把这个文献脚本升级为英文论文自动化流水线

最近我读了一个很实用的小仓库：它已经具备**英文文献自动整理的雏形**，但距离“批量稳定处理 + 后续可分析”还差几步。本文用一篇短文梳理当前框架，并给出可落地的改造建议。

---

## 一、现有框架：结构清晰，适合快速起步

仓库当前主线非常直接：

1. `papers_raw/` 放原始 PDF。
2. 运行 `scripts/paper_organizer.py`。
3. 脚本提取标题/作者/年份/DOI，统一重命名，输出到 `papers_text/`。
4. 同时生成 `outputs/literature_list.csv` 与 `xlsx` 清单，带 `duplicate` 去重标记。

优点：**上手门槛低、流程闭环完整**，非常适合个人项目从 0 到 1。  
现状中的文本提取能力由 `src/reader/pdf_reader.py` 提供，已具备按页拼接全文文本的基础能力。

---

## 二、为什么还不够“英文文献自动化”

在真实英文论文场景下，常见痛点有三类：

- **元数据不稳定**：很多 PDF 内嵌 metadata 不完整，标题和作者可能缺失或脏数据。
- **去重不稳**：当前去重 key 主要基于 `doi+title+author`，对标题大小写、空白符、版本稿（preprint/published）容错不足。
- **缺少可追溯处理链**：脚本一次跑完，但没有日志、异常分级、增量处理与失败重试机制。

---

## 三、面向英文文献的 6 条改造建议（按优先级）

### 1）把“提取”改为分层回退（最高优先级）

建立 metadata 提取优先级：

`PDF内嵌 metadata → 首页规则抽取 → Crossref/OpenAlex DOI 回填 → 人工待确认`

这样能显著提升英文论文标题、期刊名、年份的命中率。

### 2）把去重升级为“强主键 + 弱匹配”

- 强主键：`normalized_doi`
- 弱匹配：`title_simhash + first_author + year`

并新增 `duplicate_reason` 字段（如 `same_doi`、`high_title_similarity`），便于审计。

### 3）新增“全文文本落盘”与分段清洗

目前已能抽取全文，但建议默认输出：

- `outputs/text/{paper_id}.txt`（原始抽取）
- `outputs/text_clean/{paper_id}.md`（清洗后）

清洗至少包括：连字符断行修复、参考文献段剥离、页眉页脚去噪。

### 4）引入批处理工程能力：日志、增量、重试

建议增加：

- `run_id` 与结构化日志（JSONL）
- 文件哈希缓存（同一 PDF 不重复处理）
- 错误分级（可重试/不可重试）

这一步决定系统能否从“脚本”升级为“流水线”。

### 5）统一配置化，避免硬编码

将目录、正则、输出格式改为 `config.yaml` 管理；不同学科（农业、医学、CS）可使用不同模板规则。

### 6）为后续 AI 分析预留标准字段

在 `literature_list.csv` 里补充：

- `paper_id`（稳定唯一 ID）
- `abstract`（可后补）
- `keywords`（可模型抽取）
- `language`、`source_db`、`ingest_time`

后续无论做综述生成、证据对比还是知识库检索，都更顺滑。

---

## 四、推荐的下一步落地顺序（两周版）

- **第 1 周**：重构 metadata 提取与去重逻辑，补日志和缓存。
- **第 2 周**：打通全文清洗输出 + 配置化 + 基础质量报告（成功率、缺失率、重复率）。

如果你也在做英文论文自动整理，这个仓库已经有不错起点。把上面 6 步补齐，它就能从“个人脚本”进化成“可复用的文献处理底座”。
